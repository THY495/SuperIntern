# 已知限制

本页分两部分：

- **证据缺口**：我们目前的验证，推广不到这些范围；
- **功能边界**：有意没做，或者只做了最小版的东西。

每条尽量写明什么情况下会碰到，以及怎么绕开。

## 证据缺口

1. **"提需求的人亲自签收"只有自动化测试覆盖。** 提需求的人在签收名单里时，负责人签了只算一票，必须等提需求的人本人签收。这条规则还没有在真实多人使用中验证过；如果签收迟迟不结，先看是不是在等提需求的人。
2. **实际运行的验证只在少数几家模型上做过**：DeepSeek，以及经 OpenRouter 调用的 Kimi。Anthropic、OpenAI、Gemini 只验证过适配层（单轮对话和工具调用循环）。「agent 会提问、验收员会打回、修正能走通」这些结论，都是在前两家上得到的。换厂商之前，建议先用小任务试一轮。
3. **只在小项目上验证过。** 最大的样本是中等规模的开源库（几千行），以及从零做出来的小应用。没有跨天的任务，也没有大仓库。语言上只验证过 Node 和 Python。
4. **多人协作没有真实团队的长期数据。** 多人流程只在模拟使用中验证过；真实团队用一周会被打断几次、误路由几次，目前还不知道。
5. **MCP、策略钩子、GitHub 闭环和邮件答复只有自动化测试覆盖。** 它们还没有在真实团队和真实仓库上长期用过。第一次用时，先在一个小项目上试一轮。

## 功能边界

1. **访问与认证**
   - **本机模式（默认）**：看板只监听 127.0.0.1。不带令牌的请求按启动看板的管理员执行，所以本机上的其它进程也能以管理员身份调接口。服务端会检查 `Host` 和来源，防的是别的网页借你的浏览器发请求，而不是本机进程。
   - **团队模式**：适合内网，不适合公网。它防什么、不防什么，见 [deploy-team.md](deploy-team.md)。
2. **通知里能答的有限**：推送带链接，点开能直接答规格取舍、结构矛盾、系统卡住、意见不一致；签收、安全审批、方案批准、上限追加、联网放行、交付要到完整的任务页。回邮件只能答规格取舍、结构矛盾、系统卡住三类。ntfy、飞书、钉钉、企业微信里没有作答的按钮。
3. **上下文整理是托底，不是常态**：单次请求超过自动整理线（默认 120k token）时，系统先删掉旧的工具输出，不够再让模型写简报重建上下文；简报会丢细节，同一步整理两次还装不下就建议拆步。上下文上限默认 150k token，对目录里填了上下文窗口的模型还会按窗口封顶；绑定小窗口模型时请在「预算与上限」里调低它，整理线会跟着压到上限的 80%。
4. **检索只有仓库地图**：每一步开头给一张按范围排序的"文件 → 符号"图，是这一步开工时的样子，中途改了文件不重算；其余靠 grep 和读文件。没有全文索引和语义检索，仓库很大时上下文仍可能先被耗尽。没装 Universal Ctags 时按语言用正则找定义，认得 JS/TS、Python、Go、Rust、Java 系、Ruby、PHP、C/C++。
5. **沙箱镜像只有两种**：Node，以及 Python（附带截图用的 Chromium）。其它语言的依赖要 agent 自己在沙箱里装（需要项目放行对应的联网域名）。podman 和 rootless docker 尚未验证。
6. **页面点验有边界**：签收前的页面截图只截页面刚加载完的样子。验收员在运行中的应用上点验时能打开页面、点、填、选，但不支持拖拽、悬停菜单、上传文件和多标签页；需要带 Chromium 的 Python 沙箱镜像和仓库根的 `si-preview.json`；只有标了 vision 的模型拿得到截图，自己加进目录的模型一律按不收图处理。
7. **测试保护只认三种语言**：交接时比对"原有测试有没有被改弱"，认得 JavaScript、Python 和 Go 的写法；其它语言的测试改动不会被标出来。「改弱就直接打回」目前只能用命令行打开。
8. **价格是估算**：费用按模型目录里记的单价计算。DeepSeek 记的是峰时价，谷时实际花费更低。请以厂商账单为准。
9. **冲突检测只看同一个事项**：两个人在不同问题上的答复，如果语义上互相矛盾（A 在 Q1 里隐含 X，B 在 Q2 里隐含非 X），系统检测不出来。
10. **同时跑的任务之间，AI 自己的假设互不比对**：同一项目里几个任务同时在跑时，各自的执行器做的小决定只在本任务内查冲突。两个任务定下互相矛盾的做法（比如错误码格式），要到合并后的测试或签收时才可能发现。人拍过板的约定会传给每个任务，但正在跑的任务要到它的下一步才看到。项目里有容易各做各的约定时，先在契约或决定里写明。
11. **任务依赖一旦建立就不能在界面上删改**：添加任务时，可以指定依赖和先后顺序，但已有任务之间的依赖关系没有编辑入口。
12. **同类事项只排在一起，不合并作答**：汇总推送和收件箱把同一项目、同一类的事项挨着放，但不判断几条问的是不是同一件事，也不能一次答几条。值班交接按轮换 + 代班（某几天整天由某人值）算；节假日只影响「1bd」和工作时间，不让值班表停。轮换名单不能拖动排序，只能移出再加。
13. **没设时区时工作时间按 UTC 算**：个人没设时区、部署时区也没设时，工作时间和状态报告的钟点都按 UTC，中国的部署会差 8 小时；「我的通知」只在浏览器时区不同时提示。请管理员先在「时间与日历」设好部署时区。
14. **邮件答复的邮箱限制**：Gmail、Outlook.com 的 IMAP 要用应用专用密码（不支持 OAuth2 登录）。不支持加号别名的邮箱（如 QQ、163）只能靠回信里的 In-Reply-To 认出答的是哪件事；个别客户端回信不带它，发件人会收到一封"认不出答的是哪件事"的说明，这时请到看板上答。
15. **项目规则与扩展的边界**：
   - **项目规则**只给执行器和验收员，规划时不读；在看板上改了规则，已经开工的任务看不到（它的工作区在开工时从项目分支切出），从之后开工的任务起生效。
   - **Skill** 的 `allowed-tools`、`paths`、`context: fork` 只记下、不生效；验收员和规划器拿不到 skill。
   - **钩子**不支持 `updatedInput`（不能改写 AI 的操作）；`.claude/settings.json` 里只认 PreToolUse；系统自带的检查（可动路径、共享路径、规则与钩子文件、验收、签收、推送护栏）不能关掉或换成钩子；钩子的运行记录只在审计里，看板上没有。
   - **MCP** 只用 server 的工具，server 反过来要求调模型、读目录、向人提问一律拒绝；只在沙箱里跑，不用沙箱的任务拿不到 MCP 工具。工具自己标的只读 / 可写不可信，所以每个工具默认每次都要人点头。
16. **审批门禁按命令的文字匹配**：AI 直接跑的命令（包括包在 `sh -c` 里、用 `&&` 连起来的）拦得住；脚本或程序内部再去调用的命令看不到，换了写法的也拦不住（例如不用 migrate、直接用 psql 执行 ALTER TABLE）。要稳妥就把整个工具列上（如 `psql*`），代价是只读的用法也要批。
17. **GitHub 闭环的边界**：只支持 GitHub；issue 每 5 分钟轮询一次，没有通用的 webhook 入口；只读 GitHub，不回帖、不改标签；CI 自动修和按评审意见改共用一个「AI 跟进」开关，不能只开其中一个；项目整体交付的 PR，修复任务合并后要人再交付一次项目，PR 才会更新。
18. **退回与扩大范围收不回**：
   - **「从这一步重来」不能一键撤销**：只给任务负责人、只对做完的步骤；已交付、已合并进项目分支、已中止或归档的任务不行（要改请添加任务）。退回前的代码留在 `refs/superintern/rewound/<id>`，要取回得用 git。
   - **批准扩大的可动路径收不回**：AI 申请扩大范围、你批准之后，这些路径写进契约，目前没有收回的入口。
19. **状态报告里"没等你拍板就定下的"只列标题**：看不出具体定了什么，要点进去看。报告不调模型写摘要，也不能发给团队外的人。
20. **WSL2 不会自己常驻**：WSL2 发行版不随 Windows 登录启动，最后一个会话退出后很快就会停掉。常驻的方法见 [deploy-linux.md](deploy-linux.md#wsl2-特有)。
21. **多语言的边界**：看板、命令行、事项正文和 AI 写给人的文字支持中文和英文，但有几处要知道：
   - **内容语言按部署统一**：同一个团队只有一种内容语言（事项正文、汇报等），每个人只能选自己的界面语言。改内容语言只影响之后新写的内容，已有的事项保持原来的语言。
   - **界面语言与内容语言不同时**，部分报错里会夹着内容语言的片段（报错的外壳按你的语言，里面引用的名称按内容语言）。
   - **给模型的提示词仍是中文**，末尾附一段"写给人看的内容用英文"的说明。英文输出靠模型遵守这段说明，实际运行的验证主要在中文上做过。
   - 命令行里几份诊断报告（复盘 replay、权限一览、模型目录检查）仍输出中文。
   - README、部署指南和已知限制已有英文版；仓库中部分其它文字仍是中文。
