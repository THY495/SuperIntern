# 已知限制

本页分两部分：

- **证据缺口**：我们目前的验证，推广不到这些范围；
- **功能边界**：有意没做，或者只做了最小版的东西。

每条尽量写明什么情况下会碰到，以及怎么绕开。

## 证据缺口

1. **"提需求的人亲自签收"只有自动化测试覆盖。** 提需求的人在签收名单里时，负责人签了只算一票，必须等提需求的人本人签收。这条规则还没有在真实多人使用中验证过；如果签收迟迟不结，先看是不是在等提需求的人。
2. **实际运行的验证只在少数几家模型上做过**：DeepSeek，以及经 OpenRouter 调用的 Kimi。Anthropic、OpenAI、Gemini 只验证过适配层（单轮对话和工具调用循环）。「agent 会提问、验收员会打回、修正能走通」这些结论，都是在前两家上得到的。换厂商之前，建议先用小任务试一轮。
3. **只在小项目上验证过。** 最大的样本是中等规模的开源库（几千行），以及从零做出来的小应用。没有跨天的任务，也没有大仓库。语言上只验证过 Node 和 Python。
4. **多人协作没有真实团队的长期数据。** 多人流程只在模拟使用中验证过；真实团队用一周会被打断几次、误路由几次，目前还不知道。

## 功能边界

1. **访问与认证**
   - **本机模式（默认）**：看板只监听 127.0.0.1。不带令牌的请求按启动看板的管理员执行，所以本机上的其它进程也能以管理员身份调接口。服务端会检查 `Host` 和来源，防的是别的网页借你的浏览器发请求，而不是本机进程。
   - **团队模式**：适合内网，不适合公网。它防什么、不防什么，见 [deploy-team.md](deploy-team.md)。
2. **通知是单向的**：ntfy、飞书、钉钉、企业微信只能推送，不能在通知里直接答题。答题要回到看板或用 CLI。
3. **上下文整理是托底，不是常态**：单次请求超过自动整理线（默认 120k token）时，系统先删掉旧的工具输出，不够再让模型写简报重建上下文；简报会丢细节，同一步整理两次还装不下就建议拆步。上下文上限默认 150k token，对目录里填了上下文窗口的模型还会按窗口封顶；绑定小窗口模型时请在「预算与上限」里调低它，整理线会跟着压到上限的 80%。
4. **没有检索层**：agent 靠 grep 和读文件来理解仓库。仓库很大时，上下文会先被耗尽。
5. **沙箱镜像只有两种**：Node，以及 Python（附带截图用的 Chromium）。其它语言的依赖要 agent 自己在沙箱里装（需要项目放行对应的联网域名）。podman 和 rootless docker 尚未验证。
6. **页面点验有边界**：签收前的页面截图只截页面刚加载完的样子。验收员在运行中的应用上点验时能打开页面、点、填、选，但不支持拖拽、悬停菜单、上传文件和多标签页；需要带 Chromium 的 Python 沙箱镜像和仓库根的 `si-preview.json`；只有标了 vision 的模型拿得到截图，自己加进目录的模型一律按不收图处理。
7. **测试保护只认三种语言**：交接时比对"原有测试有没有被改弱"，认得 JavaScript、Python 和 Go 的写法；其它语言的测试改动不会被标出来。「改弱就直接打回」目前只能用命令行打开。
8. **价格是估算**：费用按模型目录里记的单价计算。DeepSeek 记的是峰时价，谷时实际花费更低。请以厂商账单为准。
9. **冲突检测只看同一个事项**：两个人在不同问题上的答复，如果语义上互相矛盾（A 在 Q1 里隐含 X，B 在 Q2 里隐含非 X），系统检测不出来。
10. **任务依赖一旦建立就不能在界面上删改**：添加任务时，可以指定依赖和先后顺序，但已有任务之间的依赖关系没有编辑入口。
11. **待办摘要是最小版**：不合并同类问题；值班交接按轮换 + 代班（某几天整天由某人值）算；节假日只影响「1bd」，不让值班表停。轮换名单不能拖动排序，只能移出再加。
12. **WSL2 不会自己常驻**：WSL2 发行版不随 Windows 登录启动，最后一个会话退出后很快就会停掉。常驻的方法见 [deploy-linux.md](deploy-linux.md#wsl2-特有)。
13. **多语言的边界**：看板、命令行、事项正文和 AI 写给人的文字支持中文和英文，但有几处要知道：
   - **内容语言按部署统一**：同一个团队只有一种内容语言（事项正文、汇报等），每个人只能选自己的界面语言。改内容语言只影响之后新写的内容，已有的事项保持原来的语言。
   - **界面语言与内容语言不同时**，部分报错里会夹着内容语言的片段（报错的外壳按你的语言，里面引用的名称按内容语言）。
   - **给模型的提示词仍是中文**，末尾附一段"写给人看的内容用英文"的说明。英文输出靠模型遵守这段说明，实际运行的验证主要在中文上做过。
   - 命令行里几份诊断报告（复盘 replay、权限一览、模型目录检查）仍输出中文。
   - README、部署指南和已知限制已有英文版；仓库中部分其它文字仍是中文。
